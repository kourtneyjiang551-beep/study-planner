# AI编程实战教学案例 SOP 设计文档

> 产品：好学伴（Study Planner）
> 日期：2026-04-03
> 状态：设计阶段

## 1. 背景与目标

将「好学伴」项目的完整实施过程，打造为一个 **AI 编程教学案例**。学员通过文档 + Prompt 模板库，能够一步一步复刻出完整产品。

### 教学工具

- **唯一工具：Claude Code** — 学员只需安装 Claude Code，所有开发工作（编码、调试、测试、部署）均在 Claude Code 中完成
- 教程记录的是**人的操作过程**：给 Claude Code 发了什么 Prompt、做了什么决策、使用了什么斜杠命令/MCP/Skills
- Claude Code 内部选择用什么工具（Write/Edit/Bash 等）是 AI 自己的事，不需要记录

### 目标受众

- **初学者**：零基础或少量编程经验，想学 AI 辅助编程
- **有经验的开发者**：已有编程基础，想学 AI 编程工作流和最佳实践
- **编程讲师/培训师**：需要可复用的教学材料

### 核心理念

- **可复刻性第一**：每个 Prompt 都是实际使用过的，不是事后编造
- **嵌入式产出**：教学文档与项目实施同步生成，确保真实性
- **过程忠实记录**：记录人的操作过程（发了什么 Prompt、用了什么命令/MCP/Skills、做了什么决策），而非事后编造理想化流程
- **分层设计**：初学者看完整说明，有经验者直接看 Prompt + 检查点
- **渐进式复杂度**：Phase 1 最手把手，逐步放手

## 4. Prompt 模板格式（实施过程记录）

每个 Prompt 文件记录的是**人的操作过程**，而非 Claude Code 内部行为。遵循统一格式：

```markdown
# [步骤名称]

## 上下文
[本步骤的背景：为什么要做这件事，当前项目处于什么状态]

## Prompt

> 以下 Prompt 可直接复制到 Claude Code 中使用

\`\`\`
[完整的、可直接使用的 Prompt 文本]
\`\`\`

## 操作过程

> 记录人在这一步中做了什么（Claude Code 自动执行的部分不需要记录）

### 手动操作记录
[按时间顺序记录人的每一步操作]
1. 发送上述 Prompt 给 Claude Code
2. Claude Code 执行完毕，检查 [xxx] 是否正确
3. （如有后续对话）追加指令：「把 xxx 改成 yyy」
4. 使用斜杠命令 `/commit` 提交代码
5. ...

### 使用的命令/MCP/Skills（如有）
[只记录人主动使用的，不记录 Claude Code 自动选择的]
- 如：使用了 `/commit` 提交代码
- 如：使用了 Claude Preview MCP 查看效果
- 如：给 Claude Code 发送了设计稿截图作为参考

### 关键决策点
[实施中需要人工判断或确认的环节]
- 如：Claude Code 提供了两种方案，我们选择了方案 A，因为...
- 如：Claude Code 询问是否使用 App Router，确认 Yes
- 如：发现效果不对，追加指令「xxx」修正

## 预期输出
[完成后应该看到的效果（而非文件列表）]
- 如：浏览器打开 localhost:3000 能看到登录页面
- 如：点击「添加科目」按钮弹出表单

## 检查要点
- [ ] [学员需要确认的事项1]
- [ ] [学员需要确认的事项2]

## 踩坑记录（如有）
[遇到的问题和修复过程]
- **问题**：[描述]
- **修复**：给 Claude Code 发送「[修复指令]」
- **结果**：[修复后的效果]

## 进阶说明
> 有经验的开发者可参考

[技术决策背后的考量、替代方案等]
```

### 记录原则

- **只记录人的操作** — Claude Code 内部选择用 Write 还是 Edit、读了哪个文件，是 AI 自己的事，不记录
- **记录所有手动干预** — 追加指令、修正、确认选择等，这些才是学员需要学的
- **记录效果而非文件** — 预期输出描述「能看到什么」而非「生成了哪些文件」

## 5. 检查点（Checkpoint）格式

每个 Phase 完成后的自测清单：

```markdown
# Phase N 检查点

## 功能检查
- [ ] [功能1] 是否正常工作
- [ ] [功能2] 是否正常工作

## 代码检查
- [ ] 项目能正常 `npm run dev` 启动
- [ ] 无控制台报错
- [ ] TypeScript 类型检查通过

## 效果对比
[与参考截图对比，确认视觉效果一致]
```

## 6. 嵌入式产出工作流

教学文档与实施过程**同步产出**，具体工作流：

1. **实施前**：根据实施计划，先写好该步骤的 Prompt 模板骨架（上下文 + Prompt 草稿）
2. **实施中**：在 Claude Code 中执行该 Prompt，同步记录**人的操作**：
   - 发给 Claude Code 的每条指令（Prompt + 追加对话）
   - 主动使用的斜杠命令、MCP、Skills
   - 需要人工确认/选择的决策点及选择理由
   - 遇到问题时发送的修复指令
   - （不记录 Claude Code 自动选择的内部工具）
3. **实施后**：补充「预期输出」「检查要点」「踩坑记录」，完善该步骤的教学内容
4. **Phase 完成后**：
   - 填写检查点文档，截图记录阶段成果
   - 完善主教程对应章节
   - **打 Git tag**（如 `phase1-complete`），学员可 checkout 对照

这确保了：
- Prompt 是真实使用过的（不是事后编造）
- 记录的是人的操作过程（学员知道自己该做什么）
- 踩坑和修复指令是真实的（学员遇到同样问题时知道怎么办）
- 检查点是实际验证过的
- 每个 Phase 有参考代码可对照（Git tag）

## 7. 分层设计策略

| 读者层次 | 阅读路径 |
|---------|---------|
| 初学者 | 主教程全文 + 每个 Prompt 的完整说明 + 检查点逐条验证 |
| 有经验者 | 跳过「知识前置」→ 直接看步骤分解 → 使用 Prompt → 检查点确认 |
| 讲师 | 主教程作为教案 + Prompt 库作为课堂练习素材 + 检查点作为作业评分标准 |

## 8. 与实施计划的映射关系

| 教学章节 | 实施 Phase | 核心教学内容 |
|---------|-----------|------------|
| 第1章 | Phase 1 (MVP) | 项目初始化、数据库设计、CRUD、计时器、主题系统 |
| 第2章 | Phase 2 (统计) | KPI 面板、ECharts 图表、Supabase 云同步 |
| 第3章 | Phase 3 (成绩) | 成绩管理、分析图表、雷达图 |
| 第4章 | Phase 4 (游戏化) | 勋章、积分、奖励兑换系统 |
| 第5章 | Phase 5 (主题) | CSS 变量、主题切换、三套主题实现 |
| 第6章 | Phase 6 (完善) | 设置、备份恢复、新手引导、响应式、测试 |

## 9. 关键原则

1. **不编造 Prompt** — 所有 Prompt 模板必须是实际在 Claude Code 中执行过的
2. **忠实记录人的操作** — 记录发了什么 Prompt、用了什么命令/MCP/Skills、做了什么决策，而非事后美化（Claude Code 自动选择的不记录）
3. **保留失败记录** — 踩坑和修复过程是最有价值的教学内容，包括给 Claude Code 的修复指令
4. **每 Phase 可独立运行** — 学员不必完成全部6章才能看到成果，每个 Phase 有 Git tag 可 checkout
5. **Prompt 可复制即用** — 学员复制 Prompt 到 Claude Code 就能得到相似结果
6. **检查点强制验证** — 确保学员没有跳步导致后续出错
7. **教 AI 协作方法，而非教代码** — 学员学到的核心能力是如何驱动 AI 完成开发，不是手写代码
